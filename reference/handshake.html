Lifetimes

Authorization code
5 minutes, single use
Access token
1 hour
Refresh token
30 days, rotated on every use

One-liners

Why a code first? The front channel leaks; only a short-lived, single-use code travels there, and tokens move on the back channel.

Why both roles in engine-service? It already owns /public-api/v1 and app resolution; the spec allows the authorization server and resource server to be the same server (RFC 6749 §1.1).
