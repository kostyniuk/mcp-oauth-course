Lesson 0004 · OAuth for the AMFG connector

Who may connect: CIMD, not DCR

A client id that is a URL, a short allowlist, and a strict match on where the browser goes back to.

After 12 minutes you can explain how engine-service decides a client is really Claude, why we allowlist on top of CIMD, why we don't support DCR, and which /authorize errors may never redirect.

The decision at /authorize

Every flow starts with GET /oauth/authorize?client_id=…&redirect_uri=…. Before anything else, engine-service must answer two questions:

  1. Is this a client we accept?
  2. Does that redirect URI really belong to it? If not, we'd post the user's code to an attacker's URL, and with a public client that is half the job done.

Three ways to know a client

ApproachHow it worksFor us
Pre-registrationAn admin registers the client by hand and hands out a random client id.Claude would need a separate registration with every MCP server in the world.
DCRThe client POSTs its details to a public /register endpoint and gets an id back.An open, unauthenticated write endpoint: anyone can create clients, call themselves "Claude", and fill the table. Deprecated by MCP 2026-07-28.
CIMDThe client id is an HTTPS URL. The server fetches it and reads a JSON document. Hosting the document on that domain is the proof of identity.No registration, no table. Advertised with client_id_metadata_document_supported: true.

{ …, "client_name": "Claude Code",
  "redirect_uris": ["http://localhost/callback", "http://127.0.0.1/callback"] }

Why an allowlist on top of CIMD

CIMD proves "this document is hosted at this URL". It doesn't prove "this is a client our customers should trust". With an open CIMD, an attacker could host https://evil.example/claude with "client_name": "Claude" and send AMFG users a link. They'd see a consent screen asking them to allow "Claude".

So OAuthClients.isAllowed accepts only the two Claude ids, plus anything in MCP_OAUTH_EXTRA_CLIENT_IDS (empty by default). Anything else gets a 400 before we fetch a thing.

The allowlist also limits SSRF: CIMD makes our server fetch a URL taken from the request, and we only ever fetch allowlisted ones.

Fetching the document safely

Limits
5 s timeout, no redirects, at most 5 KB, only HTTP 200 accepted.
Validation
client_id inside must equal the URL; redirect_uris must be non-empty; no client_secret; auth method none or absent.
Cache
A good document is cached for 5 minutes.
Pinned fallback
claude.ai's bot protection sometimes blocks server-side fetches (claude-ai-mcp#650). We then use our built-in copy of Claude's document, cached only 60 s so we retry the live one soon.

Matching the redirect URI

The requested redirect_uri must exactly equal one in the client's document, string for string. There are two refinements:

  • Loopback ignores the port. Claude Code starts a tiny local server on a random port each time, so http://localhost:53682/callback matches the registered http://localhost/callback (RFC 8252 §7.3). This only applies to http on localhost, 127.0.0.1 or [::1].
  • No fragments. OAuth 2.1 bans # in redirect URIs. We check the raw string, because a bare # leaves URL.hash empty and would slip past a parsed check.

Two kinds of error

If the client or the redirect URI is wrong, we can't redirect: we'd be sending the browser, with an error, to a URL nobody vouched for. That is an open redirector (RFC 6749 §4.1.2.1). So those errors get a plain 400 page.

Every other problem (no state, no S256 challenge, a wrong resource, a response_type other than code) goes back to the now-trusted redirect URI as ?error=…&error_description=…&state=…&iss=…, so Claude can show the user a proper message.

Defend it. A reviewer asks: "Every MCP tutorial shows Dynamic Client Registration. Why didn't we build it?"
DCR is a public, unauthenticated endpoint that writes rows: anyone could register clients with any name and grow the table, and MCP 2026-07-28 deprecates it in favour of CIMD. With CIMD, Claude's client id is a URL on claude.ai, so there's nothing to register or store. We still allowlist the two Claude ids, so a look-alike "Claude" hosted elsewhere is refused before we even fetch it.
