The 60-second pitch

Explain the whole feature to a teammate who has never seen it: what, why, and the four or five design decisions that matter. Write it, then compare.
Users can now connect Claude to AMFG by pasting https://console.amfg.ai/mcp; no admin has to hand out an Incoming Secret. Claude discovers our authorization server from a 401 and two well-known documents. It sends the user through the normal Management Console login to a consent screen, then swaps a 5-minute code for a 1-hour access token and a 30-day refresh token.

Five decisions carry it. PKCE S256, because Claude has no client secret. CIMD with an allowlist, so there's no registration endpoint and no fake "Claude". Tokens are opaque, hashed, bound to /mcp, with rotation and family-wide revocation on replay. Scopes are read and write, with step-up, and tools run with the same app identity as Incoming Secrets. And it's routed with three Exact ingress rules plus an in-app rewrite, gated by MCP_OAUTH_ISSUER, so it ships dark until prod has deployment template 4.0.8+.

Cheat sheet

Lifetimes
code 5 min · access 1 h · refresh 30 d, rotating
Scopes
mcp:read · mcp:write · offline_access
Errors
401 no/bad token · 403 insufficient_scope · 400 invalid_target
Kill switch
MCP_OAUTH_ISSUER unset → /oauth 404, no challenge
Clients
claude.ai + Claude Code CIMD ids, pinned fallback
Prod blockers
template bump · release port · issuer env · directory listing
